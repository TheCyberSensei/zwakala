# Project instructions

These instructions apply throughout this repository.

- Read existing project files and applicable instructions before editing.
- For complex changes, explain the plan before implementation. Record whether formal Plan Mode was actually used; do not equate a written plan with that mode.
- Make small, focused, reviewable changes.
- Explain significant architectural decisions and record their rationale in `docs/decisions.md`.
- Use appropriate tests and validation where practical. Report actual results, failures and checks that were not run.
- Distinguish verified evidence, participant observations, assumptions and open research questions. Record sources for factual claims.
- Never fabricate sources, research findings, quotations or test results.
- Avoid unnecessary dependencies and infrastructure.
- Prioritise sound architecture, reliable implementation, meaningful tests, evidence-based research, security and privacy. Investigate competing explanations and contradictory evidence; distinguish frontline observations from direct evidence about customers.
- The 11 November 2026 deadline is not permission to rush or reduce quality. Keep engineering simple without cutting corners. Present genuine scope, quality and time conflicts for the participant's decision.
- Preserve approved survey wording and settings. Survey-design changes require human approval and a recorded decision; regenerate the runtime specification and review its tests after approved changes.
- Preserve respondent privacy. Keep identifying information and private research out of tracked files, logs, examples and test fixtures. Prefer storing private material outside the repository; use synthetic data for validation.
- Never commit credentials, tokens, API keys or private research data. Review intended changes before staging or committing. Do not force-add ignored private material.
- Obtain explicit approval before publishing surveys, sharing data, deleting resources or accessing external accounts.
- Obtain explicit approval before creating remote repositories or pushing repository content.
